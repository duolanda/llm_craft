# LLMCraft 想法与方向

## 玩法

- [x] 拿人机当 baseline：一种几乎随机决策的电脑（`random`），一种先生产几个农民采集然后无脑爆兵冲基地的电脑（`rush`）。检验标准：LLM 对 `rush` 胜率不到 80% 说明设计有问题，对 `random` 胜率不到 50% 说明问题大了。
- [x] 更宏观、更持久的战略 + 临场反应分层：多 tick Mission / `orchestrate_plan` 已提供持续计划层，`GameplayController.handleCommittedTick` 在每个 committed tick 推进计划与持续攻击。
- [x] 让 AI “主动看”：相比每轮灌大量 status，改成模型主动选择查看不同区域的信息。人类玩家的高频切屏本身就是新手老手的分界，AI 也可以走这条路。
- [ ] worker 修建筑。
- [x] tank 碾压步兵
- [ ] `light_tank` 移动射击：执行 attack move 时保持行进，并在射程内按武器冷却开火；普通 move 仍不主动索敌，其他兵种暂不获得该能力。
- [ ] AI 还没有主动控制坦克开过去把兵压死的意识
- [ ] 是不是可以考虑让多模态 AI 能直接看到战场
- [ ] 单位经验与晋升：兵种可通过战斗或存活积累经验，依次升级为“老兵”“精英”，获得适度属性或能力强化，并在外观上清晰区分；具体经验来源、升级收益和滚雪球限制后续再设计。

## Agent / 控制面要重新评估的

- [ ] `state_stale` / `no_recent_read` 警告还有必要吗？现状是 `AgentPolicy` 跟踪 lastReadTick，距离太久会在动作结果里插 `state_stale` 警告、从未读过会插 `no_recent_read`。但 LLM agent 从上次 tool 调用收到完整状态后跳几个 tick 再动手是正常节奏，这种 “提醒重读” 是不是多余的噪声、有没必要保留，甚至会不会反而诱导模型反复读同一个工具（参考已知问题 #6 只读工具偏碎）？需要先评估。

## 长期方向

- [ ] 强制攻击 / 友军伤害：如果 AI 会打友军，会有节目效果。
- [ ] 迷雾：RTS 的底线，目前战术迷雾尚未实现（只有渲染层 atmospheric fog）。
- [ ] 允许用户新建一个 agent，用户可以给自己的提示词，并且有跨轮次记忆 
- [ ] 赛季机制：避免有人找到万能解法。例如 worker 采集量减半鼓励前期 rush、Barracks 造价减半鼓励爆兵、HQ 血量减半放大偷家收益等。
- [ ] 类 War3 的地图编辑器：当 RTS 核心成熟后，地图编辑器会是加分项，理论上 LLM 几乎可以玩任意地图。
